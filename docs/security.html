安全与隐私

一个能读文件、跑命令、连外部服务的智能体,安全边界必须写在明面上。这一页说明 XINCODE 怎么管权限、怎么管密钥、以及哪些事情它做不到。

Permission modes

权限模式:先问,再动手

应用提供两种权限模式:询问与完全访问。默认是前者——涉及敏感面的操作(写文件、执行命令、访问外部服务等)会先停下来等你确认。

模式之外还有一层策略判定:执行策略与权限求交在动手前完成,不满足条件的调用会被拦下,而不是执行到一半再报错。

Approval

敏感操作审批:真的停下来

  • 确认卡——敏感操作在对话里出现确认卡,写清要做什么、影响哪些文件或命令。
  • 通知栏批复——任务在后台跑时,直接从通知栏同意或拒绝,不必回到应用。
  • 无回执不执行——审批是真的暂停执行链:飞行模式下点同意也无效,必须有回执才继续。
  • 拒绝可重判——模型会拿到你的拒绝理由,换一个方案重试,而不是卡死到超时。

Audit

审计日志:事后能对账

工具调用、审批结果与关键动作都会留下记录。做过的每一步都能回看,而不是只留一句"已完成"。长任务的运行流水会落盘,因此既支持续跑,也支持事后复盘。

Secrets

密钥与本地数据

  • API Key 只在本机——经 Android Keystore 加密的配置存储落库;正式包不包含任何 Key。
  • 插件 Key 只进请求头——需要 Key 的在线插件,Key 加密落库后直接注入请求头,绝不进入模型上下文。
  • MCP 授权头加密——远程 MCP 的 Authorization 头(含 GitHub OAuth Token)统一加密存放。
  • 生图不转发 Key——下载图片时不把 API Key 附带发往第三方地址。
  • 关闭系统备份——android:allowBackup="false",不参与系统自动备份。

Network

出站与插件边界

  • NetGuard 出站守卫——只放行公网 http(s);localhost、环回地址、私网与保留地址一律拒绝,避免插件把你的设备当成跳板(SSRF 防护)。
  • 守卫看最终 URL——地址校验放在路径替换之后,防止用拼接绕过。
  • 响应截断——插件响应截断到 4000 字符,单次调用无法把上下文或界面撑爆。
  • 上架前实测——每个在线插件端点上线前都调通返回 200 才收录。

Privacy

隐私边界

为了说清楚"数据去了哪里",这里是完整的情形:

数据流向
数据去向
对话内容与工具结果发送到你自己配置的模型服务(否则模型无法生成回答)
联网搜索关键词发送到你启用的搜索引擎
插件调用参数发送到该插件对应的服务
MCP 工具调用发送到你启用的 MCP 服务器(本地 stdio 形态不出设备)
API Key / Token只发往其对应的服务,用于鉴权;不进入模型上下文
使用统计不存在:无广告 SDK、无第三方分析、无账号体系

Limits

做不到的事

写清楚边界比堆承诺更有用:

  • 不保证模型输出正确——智能体会给出证据与过程,但最终判断仍在你;涉及不可逆操作时请保持审批模式开启。
  • 不控制你的模型供应商——数据到了对方服务之后,由对方的条款与地区法规约束,请自行评估并选择合适的供应商。
  • 不代管密钥——没有云端托管,也不提供共享 Key;换设备需要自己重新填。
  • Root 意味着更大权限——Root 环境下终端可做的事更多,请在清楚风险的前提下使用。
  • 开源不等于无漏洞——代码可被审计,但仍可能有未发现的缺陷。

This site

本站自身的防护

文档站同样是攻击面,所以本站按下面的方式收敛:

  • 内容安全策略(CSP)——每个页面都下发严格的 script-src 'self':不加载任何第三方脚本,也不允许内联脚本执行。首屏主题脚本已外置成独立文件,因此不需要 unsafe-inline。
  • 零第三方依赖——CSS、JS、字体、图标与图片全部同源自托管,没有 CDN、没有统计脚本;因此也不存在第三方被劫持后连带本站的风险。
  • 防框架嵌套——对 iframe 套壳(点击劫持)做了脚本层防护;需要说明的是,GitHub Pages 无法下发 X-Frame-Options / frame-ancestors 响应头,这一层做不到浏览器级强制。
  • 外链一律隔离——所有站外链接都带 rel="noopener noreferrer",避免新窗口通过 window.opener 反向操作本站。
  • 不接收用户输入——全站没有表单、没有登录、没有可写接口,不存在注入或数据落库面。
  • 构建期校验——仓库的 CI 会检查内部链接与锚点、图片替代文本、CSP 是否在位,防止后续改动把站点改坏。

内容层面的授权边界(哪些可以引用、哪些属于冒名)写在版权与使用。

Report

报告安全问题

如果发现安全缺陷,请优先使用仓库的私密渠道报告,而不要直接公开细节:

提交安全公告 普通 Issue
