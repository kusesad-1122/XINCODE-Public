# 导航、权限与设置重构设计

## 背景

当前应用的侧边栏将 GOAL、群聊房间与 IDE/MCP/Skills 分散在多个区域，短说明在窄屏上出现裁切；设置页仍保留部分已经放入侧边栏的入口。

权限卡目前只读取当前权限层级。点击「查询」只是递增组件内部的刷新计数，没有持久化的执行权限选择，也没有把查询过程、选定层级和不可用原因展示出来。

供应商市场与供应商配置由两个页面承载，设置页因此出现两个相近入口。此次重构统一导航与页面归属，但不改变已有配置数据和功能实现。

## 目标

- 侧边栏顶部按固定顺序提供五个直接入口：GOAL 模式、群聊房间、IDE、MCP、Skills。
- 为五个入口提供稳定的标题与说明布局，保证窄屏上不出现半行文字或相互覆盖。
- 将群聊、MCP、Skills、IDE 相关入口从设置首页移除；IDE 内部继续承载环境配置和代码工具。
- 将供应商市场和供应商配置合并到一个入口，默认先展示我的配置。
- 让权限分析同时支持查询、执行权限选择、状态反馈和实际执行策略。

## 范围边界

- 不修改 Goal、群聊、IDE、MCP、Skills 页面内部的业务功能。
- 不改变 Agent 的「询问 / 计划 / 完全访问」操作策略；它与 Root、Shizuku、普通执行层级分离。
- 不迁移或删除供应商配置、模型列表、群聊房间、Goal 会话和其他数据库数据。
- 不把任何 API Key、访问令牌或设备权限信息写入源码、日志或发布说明。

## 设计

### 1. 侧边栏导航

`SidebarContent` 改为由“顶部导航区 + 可滚动内容区 + 设置底栏”组成。顶部导航区位于「新对话」之后、搜索框之前，五项使用同一个入口行组件。

固定顺序为：

1. GOAL 模式
2. 群聊房间
3. IDE
4. MCP
5. Skills

每个入口行具有以下稳定布局：

- 图标、标题和箭头在同一行；标题单行显示，超长标题使用省略号。
- 说明文字位于标题下方，最多两行，行高固定，入口行使用足够的最小高度容纳完整内容。
- 点击整行只触发一个页面导航回调，并关闭抽屉；不再通过多个分组标题和重复行表达同一入口。
- 入口区不使用 `DEVELOPER` 标题，避免 IDE、MCP、Skills 被再次分组或重复出现。

GOAL 和群聊的已有数据仍可快速访问：入口行下方可以显示对应的紧凑预览行，GOAL 预览直接打开目标会话，群聊预览直接打开房间；预览不再显示第二个「GOAL 模式」或「群聊房间」标题。没有数据时只显示入口行，不插入被截断的长说明。

搜索、普通会话、项目、身份切换和设置保留在导航区之后。普通会话和项目继续使用 `LazyColumn`；设置底栏保持始终可点击。侧边栏窄屏布局不得依赖固定宽度文本，内容区由滚动容器承载。

五个入口的导航目标分别为 `goal`、`group_rooms`、`ide_dashboard`、`mcp` 和 `skills`。从侧边栏进入的页面返回聊天页；IDE 子页继续使用现有的来源页返回规则。

### 2. 设置页去重

`SettingsScreen` 只保留设置和配置类功能。账户与模型区域只保留一个「供应商」入口，点击后进入统一供应商页面。

以下入口不再在设置首页渲染：

- 群聊房间
- MCP
- Skills
- IDE 总览
- IDE 的环境配置
- IDE 的代码索引

这些页面仍由侧边栏或 IDE 页面内部进入。设置页中与 Git、日志、用量、看板、工作区、模型委托、功能模型等非重复配置相关的能力继续保留。

`MainActivity` 不再为设置页传递已移除入口的回调，设置内部页面统一以设置页为父页面；侧边栏入口对应的页面使用聊天页为父页面。未知或失效路由继续回到聊天页，不创建第二套导航状态。

### 3. 供应商统一页面

新增统一的供应商页面容器，由它拥有当前视图状态和返回行为。页面提供两个同级视图：

- 「我的配置」：复用现有供应商配置表单、API Key Keystore 加解密、模型拉取、手动模型 ID、能力声明和启用配置。
- 「供应商市场」：复用现有免费额度、订阅套餐和按量付费列表，以及官网跳转、一键添加和 OAuth 设备码流程。

默认视图为「我的配置」。两个视图可以使用顶部标签切换，但只能有一个页面标题、一个返回按钮和一个数据刷新回调。切换视图不重置已保存配置，不重复创建数据库状态。

供应商市场与配置共用当前的 `AppDatabase`、`KeystoreProvider`、`OpenAiClient` 和 `onConfigChanged`。供应商入口合并只改变页面组合和路由，不改变 ProviderConfigEntity、模型列表或密钥存储格式。

`model_market` 不再作为设置入口路由；统一页面处理市场视图。返回统一回到设置页，供应商保存、激活、删除和市场添加后的运行时刷新行为保持现有语义。

### 4. 权限分析与执行选择

新增独立于 `PermissionMode` 的系统执行权限偏好：

`ExecutionTierPreference` 包含：

- `AUTO`：按 Root > Shizuku > 普通自动选择。
- `ROOT`：只允许 Root；Root 不可用时明确失败，不降级。
- `SHIZUKU`：只允许已授权的 Shizuku；不可用时明确失败，不降级。
- `NORMAL`：只使用普通应用沙盒，不请求 Root 或 Shizuku。

该偏好按应用保存，默认值为 `AUTO`。权限执行器是唯一解析偏好的边界：

- `currentTier` 继续表示设备当前检测到的实际层级，不把“已安装但未授权的 Shizuku”误报为可执行层级。
- `resolveTier` 根据偏好和检测结果返回实际执行层级或明确的不可用原因。
- `execute` 和 `executeStreaming` 按解析结果执行；指定层级不可用时返回失败结果，普通模式直接进入普通 shell，自动模式保留现有降级顺序。
- 所有生产工具使用统一执行器，不在 UI 或单个工具中添加补偿性降级。

权限卡改为“权限分析”卡：

- 显示当前偏好、当前检测到的最高可用层级、实际执行层级和查询结果。
- 提供权限选择控件，选择后立即保存，并在目标层级不可用时显示原因。
- 「查询」执行一次 Root、Shizuku 和普通层级检测；查询期间显示进行中状态，完成后更新结果，而不是只改变一个不可见计数。
- Shizuku 已安装但未授权时显示「请求授权」；授权回调完成后自动重新查询。
- Root 状态查询复用现有 `RootDetector` / `RootShellManager` 检测链路；不把诊断命令的输出当作授权成功的唯一依据。
- 权限卡中的选择只影响系统命令执行层级，聊天输入框中的 Agent 操作策略保持独立。

### 5. 状态与错误处理

- 页面导航回调只负责改变 `currentPage`，不在侧边栏复制页面数据。
- 供应商视图切换和权限偏好保存使用 Compose 可观察状态；回到页面后从数据库或偏好重新加载。
- Root、Shizuku 检测异常必须转成可见的失败原因；不吞掉异常后留下“查询无反应”的空状态。
- 指定 Root 或 Shizuku 执行失败时返回带原因的 `ExecResult`，调用方按现有错误卡展示；不自动改用更低权限。
- 普通模式不得调用 RootShellManager 或 ShizukuShell；自动模式才允许按优先级尝试。
- 查询失败不修改用户已经选择的偏好；重新查询成功后才更新可用状态。

## 数据流

```text
侧边栏五入口
  ├─→ currentPage ─→ Goal / 群聊 / IDE / MCP / Skills
设置 → 供应商
  └─→ SupplierHubScreen ─→ 我的配置 / 供应商市场

执行权限偏好
  ├─→ persisted app preference
  └─→ PrivilegedExecutor.resolveTier
        ├─→ Root
        ├─→ Shizuku
        └─→ 普通 shell
```

## 组件与文件职责

- `SidebarContent.kt`：只负责入口布局、列表预览和侧边栏交互，不承载页面业务。
- `MainActivity.kt`：维护页面路由、父页面返回规则和统一供应商页面的依赖注入。
- `SettingsScreen.kt`：渲染设置项、去重入口和权限分析卡。
- `SupplierHubScreen.kt`：维护供应商双视图；配置与市场内容拆为内部可复用内容。
- `SupplierConfigScreen.kt` / `ModelMarketScreen.kt`：保留领域表单和市场流程，改为被统一页面复用，避免重复实现。
- `privilege/PrivilegedExecutor.kt`：保存偏好解析和执行层级选择的唯一运行时边界。
- `privilege` 相关检测实现：提供 Root、Shizuku 可用性和授权状态，不在界面层复制检测规则。

## 验收标准

1. 侧边栏顶部只出现五个直接入口，五项说明在窄屏完整显示；不再出现 `DEVELOPER` 分组或重复的 Goal、群聊、MCP、Skills、IDE 设置入口。
2. 点击五个入口都能进入对应页面；Goal 任务和群聊房间预览仍能打开具体会话或房间，返回路径正确。
3. 设置页账户与模型区域只有一个「供应商」入口；统一页面默认打开「我的配置」，切换到市场后现有添加流程可用。
4. 权限分析首次显示 `AUTO`，点击「查询」有加载和完成反馈；选择四种执行偏好后状态立即可见，目标层级不可用时显示明确原因。
5. 自动、Root、Shizuku、普通四种策略在执行器单测中分别证明：自动可降级，指定层级不降级，普通不接触高权限执行器。
6. 现有供应商配置、模型、群聊、Goal 和数据库迁移行为不受影响；不出现密钥或令牌泄漏。
7. 对改动模块执行仓库可用的最低成本编译或测试检查；若环境仍缺少 Windows Gradle 入口，明确记录为验证阻塞，不修改项目基础设施。
